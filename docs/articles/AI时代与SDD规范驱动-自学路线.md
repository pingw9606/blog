# AI 时代还要学开发吗 —— SDD 规范驱动与 AI 工程化自学路线

> 起因：看到一门课《SDD 规范驱动 + Harness 驾驭工程 · AI 全栈开发》（¥269，初阶，19 小时），纠结"AI 时代这课还有意义吗"。
> 这篇把结论、判断依据、以及一条**免费自学路线**讲清楚。配合本站《Kiro 规范接入》一起看。

---

## 一、先给结论

AI 时代真正贬值和升值的能力，是**两拨人**：

| 贬值（AI 正在替代） | 升值（AI 时代更值钱） |
|--------------------|----------------------|
| 手敲 CRUD、拼样板代码 | 把模糊需求拆成清晰**规范/spec** |
| 背 API、记语法 | 架构设计、技术选型、边界拆分 |
| "照着文档抄"式开发 | **审查 AI 产出**、把控质量与安全 |
| 单点小功能实现 | 端到端交付、工程化流程设计 |

> 一句话：**会写代码**在贬值，**会指挥 AI 交付可靠系统**在升值。像那门课讲的 SDD（规范驱动）、驾驭 Agent 做工程，方向正好踩在升值侧——所以"有没有意义"这个问题本身问反了，它恰恰是 AI 时代的核心技能。

真正该纠结的不是"要不要学"，而是"**要不要花钱买这门课**"。

---

## 二、什么是 SDD（Spec-Driven Development，规范驱动开发）

### 2.1 它解决什么痛

早期用 AI 写代码 = "随便聊两句让它写" → 结果：

- AI 猜需求，猜错方向，返工；
- 生成一大坨，你看不懂也不敢改；
- 没有约束，风格、安全、性能全凭运气。

SDD 的思路：**先把需求和约束写成规范，再让 AI 按规范生成**。规范成为人和 AI 之间的"合同"。

### 2.2 SDD 的核心三件套

| 文档 | 回答的问题 | 内容 |
|------|-----------|------|
| **requirements** | 做什么 | 用户故事、验收标准（EARS 语法：When…the system shall…） |
| **design** | 怎么做 | 架构、数据模型、接口、时序、错误处理 |
| **tasks** | 拆成哪些步骤 | 可勾选的实现任务清单，逐条让 AI 执行 |

> 流程：**需求对齐 → 设计评审 → 拆任务 → AI 逐条实现 → 人审查**。每一步人都在"掌舵"，AI 负责"划桨"。这就是 Kiro / Amazon 内部、越来越多团队在推的开发范式。

### 2.3 为什么它在 AI 时代才火

因为 AI 生成能力够强了，瓶颈从"写得出来"转移到"写得对不对、可不可控"。规范就是**把控制权还给人**的手段——你定义清楚边界，AI 在边界内高效发挥。

## 三、AI 工程化：从"能生成"到"能交付"

会让 AI 写出一个函数，和能用 AI 交付一个可靠系统，中间隔着**工程化**。核心能力拆解：

### 3.1 规范与约束（Steering / Rules）
把团队编码规范、安全红线、性能要求写成 AI 常驻规则，让每次生成都自动遵守。（参考本站《Kiro 规范接入》里的 steering 机制。）

### 3.2 上下文工程（Context Engineering）
- 给 AI **喂对上下文**：相关代码、接口定义、约定，而不是让它瞎猜。
- 控制上下文体积：常驻规则要短，重文档按需加载（skills 思想），避免"上下文爆炸"。

### 3.3 自动化关卡（Hooks / CI）
- 提交前自动 Code Review、提交后自动沉淀经验；
- 不依赖"AI 自觉"或"人记得"，用事件强制触发。

### 3.4 审查与验证（最不可替代的能力）
- AI 会自信地写出**看起来对、其实错**的代码；
- 你要能读懂、能测试、能发现安全/性能/边界问题。
- **这是 AI 时代护城河最深的能力**——它要求你比 AI 更懂业务和系统。

### 3.5 经验沉淀（Learnings）
把踩过的坑、定过的规范固化下来，随仓库同步，让 AI 下次自动复用，团队能力滚雪球。

## 四、那门课到底值不值 ¥269

按人群分：

| 你的情况 | 建议 | 理由 |
|---------|------|------|
| 转型新手 / 想系统建立 AI 工程化思维 | **可以买** | 帮你把零散认知串成方法论，少走弯路 |
| 已在实战用 AI 写代码（Cursor/Claude/Kiro） | **不必买** | 大部分内容自己摸索两周就会，不如省钱看免费资料 |
| 只想追热点、没有真项目练手 | **别买** | 光看不练，什么课都没用 |

**三个冷静判断点：**

1. **初阶 + 19 小时**：深度有限，资深的人吃不饱。
2. **AI 工具迭代极快**：课里具体的 Harness 用法、prompt 技巧半年就可能过时；能留下的是**方法论（SDD 思维）**，留不下的是具体操作。
3. **169 人 + 满分 10.0**：样本太小，早期评分参考价值低。

> 结论：**方向对，但对多数已入门的人，钱可以省**——方法论是公开的，动手做个真项目比看课学得快。

## 五、免费自学路线（替代报课）

### 阶段 0：建立心智（半天）
- 读 Kiro / GitHub Spec-Kit 关于 **Spec-Driven Development** 的介绍，理解 requirements/design/tasks 三段式。
- 想清楚一句话：**AI 是执行者，你是设计者和审查者**。

### 阶段 1：把工具用起来（1 周）
- 选一个 Agent 工具（Kiro / Cursor / Claude Code 等），跑通"对话式写代码"。
- 刻意练习：**先写清需求再让它写**，对比"直接让它写"的差距。

### 阶段 2：规范驱动做一个真项目（2–3 周）
- 选个你真想做的小全栈项目（比如一个带后端的工具站）。
- 严格按 SDD 走：
  1. 写 `requirements.md`（用户故事 + 验收标准）；
  2. 写 `design.md`（架构 + 接口 + 数据模型）；
  3. 拆 `tasks.md`，逐条让 AI 实现；
  4. **每条产出都自己审查、测试**。
- 把项目部署上线（呼应本站《全栈重构实战》系列）。

### 阶段 3：工程化沉淀（持续）
- 给项目加 steering 规则（编码规范、安全红线）；
- 配 commit 前自动 Code Review 的 hook；
- 把踩坑写成 learnings，让 AI 复用。
- 参考仓库：[github/spec-kit](https://github.com/github/spec-kit)、[alan2207/bulletproof-react](https://github.com/alan2207/bulletproof-react)（工程化范本）。

### 阶段 4：能力升级（长期）
- 深化**审查能力**：AI 写的代码，你能不能一眼看出安全/性能/边界问题？
- 深化**架构能力**：系统怎么拆、边界怎么定——这是 AI 最难替代、也最值钱的部分。

## 六、面试怎么讲（把这些变成谈资）

> "我现在的开发模式是**规范驱动 + AI 执行**：需求先落成 spec（requirements/design/tasks），让 AI 在明确约束下生成，我负责架构设计和产出审查。我还把团队规范做成 AI 常驻规则、把 Code Review 做成提交时自动触发的 hook，让质量关卡零成本执行。**AI 提升的是我的交付吞吐，但设计和把关始终在我手上**——这也是我认为 AI 时代工程师的核心价值所在。"

---

## 七、一句话总结

- **课有没有意义**：方向完全正确，SDD 和 AI 工程化就是 AI 时代的核心技能。
- **要不要买**：已入门就省钱自学，方法论公开、动手最快；纯新手可买来建立体系。
- **真正要练的**：拆规范、定架构、审产出——**会指挥 AI，而不是被 AI 替代**。
