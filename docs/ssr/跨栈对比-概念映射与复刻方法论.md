# Nuxt 3 → Next 16 复刻实战：概念映射全表 + 迁移方法论

> 本篇是「SSR 项目实战」课题的**总纲**。我们把一个 Nuxt 3（Vue）短剧 SEO 站，跨技术栈复刻重写成 Next 16（React App Router）。这篇给出两套框架的**完整概念映射表**，以及"哪些能直接照搬、哪些必须重新设计"的迁移方法论。后续 Nuxt 篇 / Next 篇会逐块展开，这里先建立全局地图。

---

## 0. 复刻的心法：复刻"行为"，不是"代码"

一句话原则：**复刻的是页面结构、业务功能、SEO 行为；实现完全用新栈重建。**
- ❌ 别把 Vue/Nuxt 写法硬翻译（Pinia store、`<script setup>`、composables、`useFetch`）；
- ✅ 用 React/Next 的地道方案重写（Server Component、next-intl、App Router）。

**为什么**：两套框架的"服务端/客户端边界""数据流""渲染模型"根本不同，逐行翻译只会写出别扭又有 bug 的代码。要按新栈的思维重构。

## 1. 概念映射全表

### 路由
| Nuxt 3 | Next 16 App Router |
|---|---|
| `pages/index.vue` | `app/[locale]/page.tsx` |
| `pages/drama/[id].vue`（动态） | `app/[locale]/drama/[slug]/page.tsx` |
| `pages/dramas/[...slug].vue`（catch-all） | `app/[locale]/dramas/[[...slugs]]/page.tsx` |
| `layouts/default.vue` | `app/[locale]/layout.tsx` |
| `middleware/*.ts` | `middleware.ts`（根级）/ 段级 layout 逻辑 |
| 文件即路由，自动注册 | 目录 + 约定文件（`page`/`layout`/`loading`/`error`） |

### 数据获取（SSR 核心差异）
| Nuxt 3 | Next 16 |
|---|---|
| `useAsyncData` / `useFetch`（组件里声明式取数） | **Server Component `async` 函数体里直接 `await`** |
| `$fetch`（命令式请求） | `fetch()`（带缓存语义）/ 数据层函数 |
| 服务端+客户端都可能跑 | RSC **只在服务端**跑，取数不进客户端包 |
| `refresh()` 重新取 | 重新导航 / `revalidate` / router.refresh |
| 客户端按需取数 | `"use client"` 组件里 `fetch` 调 route handler（`/api/*`） |

### 状态管理（最需要"重新设计"的地方）
| Nuxt 3 | Next 16 |
|---|---|
| **Pinia** 全局 store | **优先 Server Component 取数、直接传 props**；不滥用全局状态 |
| store 里存服务端数据 | 服务端取好数据 → 作为 props 下传给（客户端）组件 |
| 跨组件共享状态 | 必要的客户端共享用 Context/`useState`，能服务端解决就不上客户端 |

### 服务端 / 客户端边界
| Nuxt 3 | Next 16 |
|---|---|
| 组件默认两端跑；`<ClientOnly>`、`process.client` 区分 | **RSC 默认只在服务端**；要交互/浏览器 API 的组件加 `"use client"` |
| — | 客户端组件**禁止运行时 import server-only 模块**（只能 `import type`） |

### 交互 / 生命周期
| Nuxt 3（Vue） | Next 16（React） |
|---|---|
| `ref` / `reactive` | `useState` |
| `computed` | `useMemo` / 派生变量 |
| `watch` | `useEffect`（带依赖） |
| `onMounted` | `useEffect(() => {}, [])` |

### 国际化
| Nuxt 3 | Next 16 |
|---|---|
| `@nuxtjs/i18n` + `vue-i18n` | **next-intl** |
| `$t('key')` / `useI18n()` | `getTranslations()`（服务端）/ `useTranslations()`（客户端） |
| `localePath('/x')` / `<NuxtLink>` | `@/i18n/navigation` 的 `Link`（自动带 locale 前缀） |
| `nuxt.config` i18n（locales/strategy） | `i18n/routing.ts`（locales/`localePrefix`）+ `middleware` |

### SEO
| Nuxt 3 | Next 16 |
|---|---|
| `useHead()` / `useSeoMeta()` | `export async function generateMetadata()` |
| 手动拼 canonical/hreflang | `alternates.canonical` + `alternates.languages`（含 x-default） |
| `nuxt.config` 或 `@nuxtjs/sitemap` | `app/sitemap.ts`（含 hreflang alternates） |
| `robots.txt` / 模块 | `app/robots.ts` |

### 视图层杂项
| Nuxt 3 | Next 16 |
|---|---|
| `<NuxtImg>`（`@nuxt/image`） | `<Image>`（`next/image`） |
| `<NuxtLink>` / `navigateTo()` | `Link` / `useRouter()`（来自 `@/i18n/navigation`） |
| `v-html` | `dangerouslySetInnerHTML` + `isomorphic-dompurify` 消毒 |
| Less/Sass + `<style scoped>` | **SCSS Modules**（`*.module.scss`） |
| 自动导入（组件/composable 免 import） | **手动 import**（无自动导入） |
| `useRuntimeConfig()` | 环境变量（`process.env`）/ `server-only` 标记 |

### 渲染与运行时
| Nuxt 3 | Next 16 |
|---|---|
| Nitro 服务端 | Node（跑在容器/pod 里） |
| `routeRules` / `prerender` | `export const dynamic` / `revalidate`（SSG/ISR/`force-dynamic`） |
| SSR / SSG / 预渲染 | SSR / SSG / ISR |

## 2. 迁移方法论：直接映射 vs 必须重设计

### ✅ 基本能直接映射（换 API 即可）
- **路由结构**：文件/目录路由几乎一一对应，动态段照搬。
- **SEO meta**：`useSeoMeta` → `generateMetadata`，字段语义一致。
- **i18n 文案**：语言包 JSON 基本能复用，调用换 API。
- **页面级数据流**：Nuxt 页面 `useAsyncData` 取数 → Next 页面 Server Component `await` 取数，思路一致。

### 🔧 必须重新设计（别硬翻译）
1. **Pinia 全局状态 → 服务端取数下传**：Nuxt 习惯把数据塞 store 全局共享；Next 里**优先在 Server Component 取好数据直接传 props**，只有真正的客户端交互状态才用 `useState`/Context。硬把 Pinia 翻成一个全局 client store 是反模式。
2. **composables → hooks + 服务端函数**：Nuxt 的 `useXxx` composable 混了服务端/客户端；Next 要拆清——数据取用服务端函数（`lib/api`），交互用客户端 hooks。
3. **scoped style → CSS Modules**：`<style scoped>` 的作用域靠编译；Next 用 `*.module.scss` + `className={styles.x}`。
4. **自动导入 → 手动 import**：Nuxt 组件/composable 自动可用；Next 全部要显式 import。

### ⚠️ 常见陷阱
- **RSC 里不能用浏览器 API / React hooks**（`window`、`useState`、`useEffect`）——那些要挪到 `"use client"` 组件。
- **客户端组件不能运行时 import server-only**（如加解密、密钥、`lib/api` 的服务端实现）——只能 `import type`，否则把服务端代码/密钥打进浏览器包。
- **读 `headers()`/`cookies()` 会让页面变动态**（不能 SSG/ISR）——Nuxt 里随手读请求，Next 里要意识到它影响渲染模式（详见《[SSR/CSR/SSG/ISR 渲染模式](../backend/SSR-CSR-SSG-ISR渲染模式-前端视角)》）。

## 3. 建议的复刻顺序

1. **搭路由骨架**：按老站 pages 结构建 app/[locale] 目录 + 空 page/layout。
2. **数据层**：把老站接口契约（端点/加解密/字段）1:1 搬到 `lib/api`（服务端）。
3. **页面取数 + 渲染**：Server Component 取数、组装页面。
4. **SEO**：`generateMetadata` + sitemap + robots，对齐 canonical/hreflang。
5. **i18n**：接 next-intl，迁移语言包。
6. **交互组件**：把需要交互的部分抽成 `"use client"` 组件（播放器、切换器、轮播）。
7. **播放器/媒体**：xgplayer → hls.js 重写。
8. **打磨**：渲染模式（哪些 dynamic）、性能、埋点。

## 4. 一句话总结

- 复刻是**按行为重建、按新栈思维重写**，不是逐行翻译。
- 路由/SEO/i18n/页面数据流**基本能映射**；**Pinia 全局状态、composables、scoped 样式、自动导入**必须按 Next 方式重新设计。
- 记牢边界：**RSC 只在服务端、client 组件不碰 server-only、读 host/cookie 会变动态**。
