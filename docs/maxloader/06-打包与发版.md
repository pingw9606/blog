# 06 · 打包与发版：electron-builder 多平台 + Release SOP

> 代码写完只是一半，得让运营装得上、用得上。本篇讲怎么用 electron-builder 一次出 mac(arm64/x64) + win 三平台安装包、未签名怎么让用户放行、以及一套可复制的发布流程（改版本 → 打包 → 分发 → 开启应用内更新提示）。

## 一、打包脚本

`package.json` 的 scripts 按环境分了几条：

```json
{
  "dev": "vite",
  "build:test":     "vue-tsc --noEmit && cross-env APP_ENV=test vite build && electron-builder",
  "build:prod":     "vue-tsc --noEmit && cross-env APP_ENV=production vite build && electron-builder",
  "build:prod:win": "vue-tsc --noEmit && cross-env APP_ENV=production vite build && electron-builder --win",
  "build:prod:all": "vue-tsc --noEmit && cross-env APP_ENV=production vite build && electron-builder --mac --win"
}
```

每条都是三步：**类型检查（`vue-tsc --noEmit`）→ vite 构建（注入 `APP_ENV`）→ electron-builder 打包**。

- `APP_ENV=production` 决定连生产接口（见第一篇 `__APP_ENV__` 注入）。不带就是 test，避免"一打包就连生产"。
- `build:prod:all` 一条命令出全平台包（mac 上可交叉打 win）。

## 二、electron-builder 配置

打包配置写在 `package.json` 的 `build` 字段：

```json
{
  "build": {
    "appId": "com.shortmax.maxloader",
    "productName": "MaxLoader",
    "directories": { "output": "release", "buildResources": "build" },
    "afterPack": "build/afterPack.cjs",
    "files": ["dist/**/*", "dist-electron/**/*", "package.json"],
    "mac": {
      "target": [{ "target": "dmg", "arch": ["arm64", "x64"] }],
      "icon": "build/icon.icns",
      "category": "public.app-category.productivity"
    },
    "win": {
      "target": [{ "target": "nsis", "arch": ["x64"] }],
      "icon": "build/icon.ico"
    },
    "nsis": {
      "oneClick": false,                        // 非静默：显示安装向导
      "allowToChangeInstallationDirectory": true // 允许用户改安装目录
    }
  }
}
```

要点：

- **`files`** 只打进构建产物：`dist`（渲染层）+ `dist-electron`（main/preload）+ `package.json`。源码不进包。
- **mac 出两个 arch**：`arm64`（M 系列芯片）+ `x64`（Intel），各一个 dmg。
- **win nsis** 设 `oneClick: false`，给用户安装向导 + 可选目录（很多公司电脑需要装到非系统盘）。
- **`afterPack`** 钩子：打包后执行 `build/afterPack.cjs`，可做一些平台特定的收尾处理。

产物落在 `release/`：

| 平台 | 文件 |
|------|------|
| macOS Apple Silicon | `MaxLoader-X.Y.Z-arm64.dmg` |
| macOS Intel | `MaxLoader-X.Y.Z.dmg` |
| Windows | `MaxLoader Setup X.Y.Z.exe` |

## 三、未签名：让用户能打开

没做苹果签名/公证、也没做 Windows 代码签名（签名要花钱，内测阶段先省）。所以用户首次打开会被系统拦，安装说明里要教他们放行：

**macOS**（提示"已损坏"或"无法验证开发者"）：
```bash
# 方法一：右键 → 打开 → 弹窗再点"打开"（只需一次）
# 方法二：终端执行
xattr -cr /Applications/MaxLoader.app
```

**Windows**（蓝框"Windows 已保护你的电脑"）：点「更多信息」→「仍要运行」。

> 打包日志里会看到 `skipped macOS application code signing` / `no signing info identified, signing is skipped`——这是预期的，不是错误。

## 四、版本号只改一处

得益于第一篇讲的 `__APP_VERSION__` 注入（vite 从 `package.json` 读版本号注入渲染层），**发版只需改 `package.json` 的 `version` 一处**：

- electron-builder 打包产物名会带上它（`MaxLoader-0.1.9-arm64.dmg`）。
- 界面侧栏左下角的版本号自动同步（`__APP_VERSION__`）。

## 五、应用内更新提示怎么触发

用户装的是老版本，怎么知道有新版？靠自建 app-service 的 `releases` 表 + `checkin`（见第五篇）。发版时往 `releases` 加一条记录：

```
POST /api/admin/releases
{
  "app_id": "maxloader",
  "platform": "all",                // 全平台通用
  "version": "0.1.9",
  "notes": "本次更新内容……",
  "download_url": "https://……飞书分发文档",
  "mandatory": false
}
```

老版本客户端启动 `checkin` 上报自己版本，服务端拿 `releases` 里最新已发布版本比对，返回 `update_available: true` + 最新版信息，客户端就弹更新条引导去下载。

> 顺序很重要：**先把安装包传到分发文档，再加 `releases` 记录**。否则用户点"前往下载"却看不到新包。

## 六、完整发布流程（Release SOP）

一套可复制的流程：

```
1. 改版本号     package.json version（如 0.1.8 → 0.1.9）
2. 提交代码     git commit + push
3. 打包         npm run build:prod:all  → release/ 出三平台包
4. 组织分发包    按平台分文件夹 + 各附安装说明.txt
5. 上传飞书文档  三平台安装包 + 新增版本更新记录
6. 加 release 记录  往 app-service releases 表加 0.1.9 → 开启应用内更新提示
7. 通知运营
```

其中 4/5 我们用一个 `分发包-vX.Y.Z/` 目录组织：

```
分发包-v0.1.9/
├─ macOS-AppleSilicon(M芯片)/  MaxLoader-0.1.9-mac-AppleSilicon.dmg + 安装说明.txt
├─ macOS-Intel芯片/            MaxLoader-0.1.9-mac-Intel.dmg       + 安装说明.txt
├─ Windows/                    MaxLoader-0.1.9-Windows-x64.exe     + 安装说明.txt
└─ 请先读我.txt                （更新内容 + 按机型分发指引）
```

## 七、几个部署侧的经验

- **服务端部署脚本要排除敏感文件**：app-service 的 `deploy.sh` 用 `rsync --delete` 时必须 `--exclude .env --exclude uploads`，否则会把生产密钥/数据覆盖掉（踩过一次坑）。
- **大文件上传飞书文档**：安装包 100MB+，用 API 传要选对类型（文件卡片而不是图片块），否则 .exe/.dmg 当图片渲染不出来。
- **Docker 构建缓存**：服务端每次 `docker compose up --build` 会攒构建缓存，攒到几个 G 时 `docker builder prune -f` 清一次。

## 小结

- 一条 `build:prod:all` 出 mac(arm64/x64) + win 三平台包；`APP_ENV` 决定连哪套接口。
- electron-builder 配置控制 appId、图标、目标格式、nsis 可改目录。
- 未签名要在安装说明里教用户放行（mac `xattr -cr` / win 仍要运行）。
- 版本号只改 `package.json` 一处，界面和包名自动同步。
- 发版流程：改版本 → 提交 → 打包 → 分发 → 加 release 记录开启更新提示 → 通知。
