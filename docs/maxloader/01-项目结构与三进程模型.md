# 01 · 项目结构与 Electron 三进程模型

> 本篇讲清楚：Electron 的三个进程各干什么、它们怎么用 IPC 通信、preload 的 contextBridge 为什么是安全关键、以及这个项目用 `vite-plugin-electron` 是怎么把三部分一起编译起来的。

## 一、目录结构

```
shortplay-uploader/
├─ vite.config.ts            # 一份配置同时编译 main / preload / renderer
├─ package.json              # scripts + electron-builder 打包配置
├─ src/
│  ├─ main/                  # 主进程（Node 环境）
│  │  ├─ index.ts            # 入口：建窗口、注册 IPC、全局异常兜底
│  │  ├─ config.ts           # 运行配置（接口地址、appService 等）
│  │  ├─ ipc/                # 各业务的 IPC handler（auth/drama/dialog/update）
│  │  ├─ http/               # 调内容中台 CMS 的 axios 封装
│  │  ├─ scheduler/          # 上传队列引擎（核心）
│  │  ├─ uploader/           # 七牛上传封装
│  │  ├─ updater.ts          # 与自建 app-service 通信
│  │  └─ utils/              # 日志、token 加密存储等
│  ├─ preload/
│  │  └─ index.ts            # contextBridge 暴露 electronAPI
│  ├─ renderer/              # 渲染层（Vue3 SPA）
│  │  ├─ views/              # 页面：drama 工作台、leaderboard 排行榜、login
│  │  ├─ layouts/            # AppLayout（侧栏 + 顶栏 + 公告/更新条）
│  │  ├─ stores/ router/ composables/
│  │  └─ main.ts             # Vue 应用入口
│  └─ shared/
│     └─ types.ts            # 主进程与渲染层共享的 TS 类型
```

一个原则贯穿始终：**能碰 Node/文件系统/网络的都在 `main`，界面都在 `renderer`，两者只通过 `preload` 暴露的窄接口用 IPC 通信。**

## 二、三进程各自的职责

| 进程 | 运行环境 | 负责什么 |
|------|----------|----------|
| **main（主进程）** | Node.js | 创建窗口、上传队列、调 CMS、读写本地文件、与 app-service 通信、全局异常兜底 |
| **preload（预加载）** | 隔离的桥接环境 | 用 `contextBridge` 把主进程能力**按需、白名单式**暴露给渲染层 |
| **renderer（渲染层）** | Chromium（无 Node） | 纯界面：Vue3 + Element Plus + Pinia + Vue Router |

为什么要这么分？因为渲染层加载的是"网页"，如果直接给它 Node 能力（`nodeIntegration: true`），一旦页面被注入恶意脚本，就能直接读写用户磁盘。所以现代 Electron 的安全基线是：**渲染层关掉 Node，通过 preload 白名单桥接**。

## 三、主进程入口：建窗口 + 安全配置 + 全局兜底

`src/main/index.ts` 里创建窗口时的关键安全配置：

```ts
mainWindow = new BrowserWindow({
  width: winWidth,
  height: winHeight,
  minWidth: 1120,
  minHeight: 720,
  center: true,
  title: `${baseTitle}${envSuffix}`,
  ...(isMac && { titleBarStyle: 'hiddenInset' }),        // mac：隐藏标题栏留红绿灯
  ...(!isMac && { titleBarStyle: 'hidden', titleBarOverlay: { /* win 自绘控件 */ } }),
  webPreferences: {
    preload: join(__dirname, '../preload/index.js'),
    contextIsolation: true,   // ✅ 上下文隔离：preload 与页面 JS 不共享作用域
    nodeIntegration: false,   // ✅ 渲染层拿不到 require / process / fs
  },
})
```

`contextIsolation: true` + `nodeIntegration: false` 是安全组合：渲染层里 `window.require` 是 undefined，只能用 preload 明确暴露的 `window.electronAPI`。

窗口默认尺寸还做了**按屏幕自适应**，避免小屏笔记本上开出屏幕外：

```ts
const { width: screenW, height: screenH } = screen.getPrimaryDisplay().workAreaSize
const winWidth = Math.min(1600, screenW - 80)
const winHeight = Math.min(1000, screenH - 80)
```

启动流程（`app.whenReady` 之后）：

```ts
app.whenReady().then(async () => {
  registerIpcHandlers()      // 注册所有 IPC handler
  await startCaptchaProxy()  // 启一个本地代理，规避滑块验证码跨域
  createWindow()
})
```

主进程还挂了**全局异常兜底**，配合后面会讲的错误上报：

```ts
process.on('uncaughtException', (err) => {
  logError('[uncaughtException]', err?.message ?? err)
  void reportError('uncaughtException', err?.message || String(err), err?.stack)
})
process.on('unhandledRejection', (reason) => {
  logError('[unhandledRejection]', reason?.message ?? reason)
  void reportError('unhandledRejection', reason?.message || String(reason), reason?.stack)
})
```

## 四、preload：白名单式暴露能力

渲染层不能直接调主进程函数，得通过 `ipcRenderer.invoke(channel, ...args)` 发消息。但如果把 `ipcRenderer` 整个丢给页面也不安全。所以 preload 里**只暴露一个精心设计的 `electronAPI` 对象**，每个方法内部封好 channel：

```ts
// src/preload/index.ts
import { contextBridge, ipcRenderer, webUtils } from 'electron'

export const api = {
  auth: {
    login: (params) => ipcRenderer.invoke('auth:login', params),
    feishuLogin: () => ipcRenderer.invoke('auth:feishu-login'),
    restore: () => ipcRenderer.invoke('auth:restore'),
    logout: () => ipcRenderer.invoke('auth:logout'),
  },
  drama: {
    search: (keyword, pageNum = 1, forceRefresh = false) =>
      ipcRenderer.invoke('drama:search', keyword, pageNum, forceRefresh),
    submit: (shortPlay, files, mode = 'add') =>
      ipcRenderer.invoke('drama:submit', shortPlay, files, mode),
    // ...
  },
  tasks: {
    list: () => ipcRenderer.invoke('drama:tasks'),
    retry: (id) => ipcRenderer.invoke('task:retry', id),
    pause: (id) => ipcRenderer.invoke('task:pause', id),
    // ...
  },
  // 监听主进程推送的上传进度事件，返回取消监听函数
  onTaskProgress: (callback) => {
    const listener = (_event, e) => callback(e)
    ipcRenderer.on('task:progress', listener)
    return () => ipcRenderer.removeListener('task:progress', listener)
  },
}

contextBridge.exposeInMainWorld('electronAPI', api)
```

几个要点：

- 渲染层里就用 `window.electronAPI.drama.search(...)`，**看不到 channel 字符串、也拿不到 ipcRenderer 本体**。
- `webUtils.getPathForFile(file)` 是拿拖拽进来的 `File` 对象真实磁盘路径的正路（新版 Electron 里 `File.path` 已废弃）。
- 进度这类主进程→渲染层的**主动推送**，用 `ipcRenderer.on` 订阅，并返回一个取消函数，方便组件卸载时 `removeListener`。

TS 类型上，把 `api` 的类型声明成全局，渲染层就有完整补全：

```ts
// 渲染层里
const res = await window.electronAPI.drama.search('855097')  // 有类型提示
```

## 五、IPC handler 的组织

主进程侧，每个业务模块注册自己的 handler，入口统一收口：

```ts
// src/main/ipc/index.ts
export function registerIpcHandlers() {
  ipcMain.handle('app:ping', () => 'pong')
  ipcMain.handle('app:env', () => config.env)
  registerAuthHandlers()    // auth:login / auth:feishu-login / ...
  registerDramaHandlers()   // drama:search / drama:submit / task:retry / ...
  registerDialogHandlers()  // dialog:pick-videos / ...
  registerUpdateHandlers()  // update:check / feedback:submit / leaderboard:get / error:report
}
```

handler 一律返回统一的 `ApiResult<T>` 形状，渲染层好统一处理：

```ts
// shared/types.ts
export interface ApiResult<T = unknown> {
  ok: boolean
  data?: T
  error?: string
}
```

```ts
ipcMain.handle('auth:login', async (_e, params) => {
  try {
    const token = await login(params)
    setToken(token); saveToken(token)
    const user = await getInfo()
    return { ok: true, data: user }
  } catch (err) {
    return { ok: false, error: err?.message ?? '登录失败' }
  }
})
```

## 六、工程：一份 vite 配置编译三部分

用 `vite-plugin-electron` + `vite-plugin-electron-renderer`，一份 `vite.config.ts` 同时编译 main、preload、renderer：

```ts
export default defineConfig({
  define: {
    __APP_VERSION__: JSON.stringify(pkg.version),  // 从 package.json 注入版本号
  },
  plugins: [
    vue(),
    electron([
      {
        entry: 'src/main/index.ts',
        vite: {
          define: {
            // 只有 APP_ENV=production 才注入 'production'，否则默认 'test'
            __APP_ENV__: JSON.stringify(process.env.APP_ENV === 'production' ? 'production' : 'test'),
          },
          build: {
            outDir: 'dist-electron/main',
            rollupOptions: { external: ['electron', 'qiniu', '@volcengine/tos-sdk', '@volcengine/openapi'] },
          },
        },
      },
      {
        entry: 'src/preload/index.ts',
        vite: { build: { outDir: 'dist-electron/preload' } },
        onstart: (args) => args.reload(),  // preload 改动自动重载
      },
    ]),
    renderer(),
  ],
  resolve: { alias: { '@': resolve(__dirname, 'src/renderer') } },
  build: { outDir: 'dist' },
})
```

两个注入值很关键：

- `__APP_VERSION__`：构建时从 `package.json` 读版本号注入，界面侧栏版本号自动同步，**发版只改 package.json 一处**。
- `__APP_ENV__`：区分连测试还是生产接口。**不用 `app.isPackaged` 判断**，避免"一打包就连生产"——`npm run build` 默认 test，只有 `build:prod`（`APP_ENV=production`）才连生产。

`rollupOptions.external` 把原生/大依赖（`qiniu`、火山 SDK）排除出打包，运行时从 node_modules 加载，避免打包体积和兼容问题。

## 小结

- 三进程分工：main 干重活、renderer 画界面、preload 做安全桥。
- 安全基线：`contextIsolation: true` + `nodeIntegration: false` + preload 白名单暴露。
- IPC 统一返回 `ApiResult`，进度用事件推送。
- 一份 vite 配置编译三部分，`define` 注入版本号和环境。
