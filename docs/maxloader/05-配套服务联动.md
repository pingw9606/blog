# 05 · 配套服务联动：更新检查 / 公告 / 排行榜 / 错误上报

> 工具主流程之外，还接了一套自建轻服务 app-service（Node + Fastify + Postgres），提供更新检查、活跃统计、公告、排行榜、错误上报、上传测速。本篇讲**客户端这一侧**怎么接——核心是一条红线：**全部失败静默、短超时、绝不阻断上传主流程**。

## 一、通信约定：x-app-key + 失败静默

所有对 app-service 的调用集中在 `src/main/updater.ts`，用一个独立的 axios（不是调 CMS 的那个 `http`），带 `x-app-key` 头鉴权，短超时，出错一律 `catch` 掉返回 null：

```ts
// config.appService = { baseUrl: 'http://124.223.111.221:8090', appId: 'maxloader', appKey: '7c07...' }

export async function checkin(userId?, userName?): Promise<CheckinResult | null> {
  try {
    const { data } = await axios.post(
      `${config.appService.baseUrl}/api/checkin`,
      {
        app_id: config.appService.appId,
        device_id: getDeviceId(),
        user_id: userId || null,
        user_name: userName || null,
        version: app.getVersion(),
        platform: detectPlatform(),   // win / mac-arm64 / mac-x64
      },
      { headers: { 'x-app-key': config.appService.appKey }, timeout: 5000 },
    )
    if (data?.ok) return { update_available: !!data.update_available, latest: data.latest ?? null, notice: data.notice ?? null }
    return null
  } catch (err) {
    logError('[checkin] 失败(已忽略，不影响使用):', err?.message ?? err)
    return null   // ★ 失败静默：app-service 挂了也不影响传剧
  }
}
```

**这就是红线的代码体现**：`timeout: 5000` + `try/catch 返回 null`。渲染层拿到 null 就当"没更新、没公告"，界面照常。

## 二、更新检查 + 公告：一次 checkin 全搞定

`checkin` 一次调用同时完成三件事：上报活跃（写统计）、返回是否有新版本、下发当前公告。渲染层在 `AppLayout` 挂载时调一次：

```ts
// renderer/layouts/AppLayout.vue
onMounted(async () => {
  const res = await window.electronAPI.update.check(auth.user?.userName, auth.user?.nickName)
  if (!res?.ok || !res.data) return
  // 有新版本且没被"忽略此版本"过 → 顶部更新条
  const latest = res.data.latest
  if (res.data.update_available && latest) {
    if (localStorage.getItem('ml_update_dismissed') !== latest.version) updateInfo.value = latest
  }
  // 有公告且没关过（按公告 id 记忆）→ 顶部公告横幅
  const notice = res.data.notice
  if (notice && localStorage.getItem('ml_notice_dismissed') !== String(notice.id)) {
    noticeInfo.value = notice
  }
})
```

两个"不打扰"设计都用 `localStorage` 记忆：

- 更新条按 **version** 记忆——"忽略此版本"后同版本不再弹，出新版本又会弹。
- 公告按 **id** 记忆——关掉某条后不再弹，发新公告（新 id）又会弹。

"前往下载"就用系统浏览器打开飞书分发文档：

```ts
function openUpdateDownload() {
  if (updateInfo.value) window.electronAPI.openExternal(updateInfo.value.download_url)
}
```

## 三、上传完成通知：飞书私聊操作人

一部剧全部传完，通过 app-service 让飞书机器人**私聊操作人本人**。触发点在上传队列里（第三篇的 `maybeNotifyBatchComplete`）：

```ts
function maybeNotifyBatchComplete(shortPlayCode?, shortPlayName?) {
  // ...判断该剧所有任务都成功、无进行中、无失败...
  const user = getCurrentUser()
  if (user?.feishuUserId) {
    void notifyUploadComplete(user.feishuUserId, shortPlayName || shortPlayCode, successCount)
  }
}
```

`notifyUploadComplete` 同样是失败静默的旁路调用——通知发不出去，绝不影响"上传其实已经成功"这个事实。用 `void` 前缀表示"发了就不管结果"。

## 四、上传测速：旁路上报

每传完一个文件，把大小、耗时、算出的平均速度旁路上报（`runOne` 成功分支里）：

```ts
const durationMs = Date.now() - uploadStartAt
if (durationMs > 0 && task.fileSize > 0) {
  const u = getCurrentUser()
  void reportUploadStat({
    userId: u?.userName,
    userName: u?.nickName,
    shortPlay: task.shortPlayName || task.shortPlayCode,
    sizeBytes: task.fileSize,
    durationMs,
    speedBps: task.fileSize / (durationMs / 1000),
  })
}
```

服务端把 IP 用离线库转成地区，后台就能按用户/地区聚合，定位"谁/哪个地区传得慢"。（我们真用它定位到过某地办公出口带宽被占满导致上传慢。）

## 五、排行榜：客户端读公开接口

排行榜数据也从 app-service 拉，用的是**公开接口**（`x-app-key`，不需要后台的 admin token）：

```ts
export async function fetchLeaderboard(days = 30): Promise<LeaderboardResult | null> {
  try {
    const { data } = await axios.get(`${config.appService.baseUrl}/api/leaderboard`, {
      params: { app_id: config.appService.appId, days },
      headers: { 'x-app-key': config.appService.appKey },
      timeout: 8000,
    })
    if (data?.ok) return { days: data.days, list: data.list || [] }
    return null
  } catch (err) {
    logError('[leaderboard] 获取失败(已忽略):', err?.message ?? err)
    return null
  }
}
```

渲染层的排行榜页拿到数据后做 Top3 领奖台 + 前十榜单，登录用户若上榜会触发庆祝动画（用 `auth.user.userName` 和榜单 `user_id` 比对判断"是不是我")。

## 六、错误上报：多层兜底 + 去重

最实用的一块。目标是**用户遇到问题时我们能看到**，尤其是接口报错。分几层捕获，全部汇到 `reportError`：

```ts
// updater.ts —— 同类错误 60s 内只报一次，防刷屏
const _errRecent = new Map<string, number>()
export async function reportError(source: string, message: string, stack?: string) {
  try {
    const msg = (message || '').slice(0, 2000)
    if (!msg) return
    const key = source + '|' + msg.slice(0, 120)
    if (Date.now() - (_errRecent.get(key) || 0) < 60_000) return  // 去重
    _errRecent.set(key, Date.now())

    const u = getCurrentUser()
    await axios.post(`${config.appService.baseUrl}/api/error-report`, {
      app_id: config.appService.appId,
      user_id: u?.userName || null,
      user_name: u?.nickName || null,
      device_id: getDeviceId(),
      source, message: msg, stack: stack?.slice(0, 8000) || null,
      platform: detectPlatform(), version: app.getVersion(),
    }, { headers: { 'x-app-key': config.appService.appKey }, timeout: 8000 })
  } catch { /* 上报失败绝不影响使用，也不再 logError 以免递归 */ }
}
```

捕获点分布在几处：

**① 接口错误（最重要）**——在 CMS 的 axios 响应拦截器统一抓，网络错误和业务 `code != 200` 都报（见第四篇）。

**② 上传失败**——队列里任务终态失败时报一次（重试中不报，防刷屏，见第三篇）：
```ts
void reportError('upload', `上传失败 ${task.fileName} [${category}] ${message}`, err?.stack)
```

**③ 主进程全局兜底**——`uncaughtException` / `unhandledRejection`（见第一篇）。

**④ 渲染层全局兜底**——Vue errorHandler + window error + unhandledrejection：
```ts
// renderer/main.ts
app.config.errorHandler = (err, _i, info) => {
  window.electronAPI?.reportError?.({ source: 'vue', message: (err?.message || String(err)) + ` [${info}]`, stack: err?.stack })
}
window.addEventListener('error', (e) => {
  window.electronAPI?.reportError?.({ source: 'window', message: e.message, stack: e.error?.stack })
})
window.addEventListener('unhandledrejection', (e) => {
  window.electronAPI?.reportError?.({ source: 'promise', message: e.reason?.message || String(e.reason), stack: e.reason?.stack })
})
```

服务端只保留最近 N 条（按条数裁剪），后台可按用户搜索。这样线上出问题时，能直接看到"谁、什么版本、什么接口、报了什么"。

## 小结

- 一条红线贯穿所有联动：**短超时 + try/catch 返回 null + `void` 旁路调用**，后端挂了不影响传剧。
- `checkin` 一次搞定活跃统计 + 更新检查 + 公告下发；更新按 version、公告按 id 用 localStorage 记忆"不打扰"。
- 通知、测速都是成功后的旁路上报。
- 错误上报分四层兜底（接口 / 上传 / 主进程 / 渲染层），同类 60s 去重，重点抓接口错误。
